## TL;DR

Code reviews catch bugs early, share knowledge, and enforce standards. Focus on readability, correctness, and design — not style nitpicks (automate those).

---

## 🔑 Key Principles

| Principle               | Details                                                  |
|-------------------------|----------------------------------------------------------|
| Review the design first | Architecture issues are costlier to fix than typos       |
| Keep PRs small          | < 400 lines for effective review                         |
| Be constructive         | Suggest alternatives, don't just point out flaws         |
| Automate style checks   | Use linters/formatters so reviews focus on logic         |
